# バックアップとデータ保護

[文書一覧](../DOCUMENT_INDEX.md)

## バックアップおよびデータ保護

実行条件とデータ保護は[バックアップとデータ保護](../POLICIES.md#バックアップとデータ保護)を参照する。

### 実行と保存先

バックアップは独立して選択できる保守操作と、更新計画内の保護工程を区別する。前者を更新の開始条件に置き換えず、後者は更新と同じ対象・計画・操作に対応付ける。利用者の入口は[実行入口](../POLICIES.md#実行入口と通常運用)、選択は[必須選択と自動実行](../POLICIES.md#必須選択と自動実行)に従う。

| 区分 | 担当 |
|---|---|
| 外部媒体側 | 内蔵OSとデータ、書き込み可能な保存先を識別し、選択済みバックアップを制御する。Live環境自身のデータを対象データとして採取しない |
| マスター側 | Cloud対象と操作・保存先の選択、SSH制御、結果の照合。接続したことだけでデータをマスターへ保存済みと扱わない |
| 対象側 | 対象の構成に合う方法でデータを整合した状態で取得し、保存・検証結果を返す。対象自身の管理記録へ対応付ける |
| 保存先 | 起動媒体・管理側・対象データとは別に、位置・機器識別・書き込み能力・容量・保全条件を確認する |

マスター自身のバックアップは物理PCの入口を使用する。保存先を外部媒体・内蔵ディスク・マスターのいずれかへ自動的に決めず、[保存の禁止条件](../POLICIES.md#バックアップとデータ保護)に照合する。

### バックアップ状態

バックアップ状態はServerSeedが直接作成したもの、またはアプリ定義で指定された確認コマンドの結果から判定する。

バックアップ成功状態は少なくとも次を含める。

```json
{
  "schema_version": 1,
  "app": "example",
  "last_success_at": "RFC3339",
  "method": "command",
  "location": "string",
  "verified": true
}
```

更新前提としての判定は[バックアップの成功条件](../POLICIES.md#バックアップの成功条件)に従う。

### 復元確認

復元確認の方法、定期実施と重要更新の停止条件は[復元確認](../POLICIES.md#復元確認)を参照する。

復元元の検証、対象OS・構成・データ種別と復元先の照合を計画へ含める。実行場所と対象場所を取り違えず、OS再導入とデータ復元を一つの無確認操作にしない。

### 未確定契約

独立バックアップ・復元のCLI、保存先の形式・対応方式・選択入力、暗号化・鍵の保全、保持・削除、保存形式の版と互換性、転送中断・容量不足・破損時の扱い、Live環境と稼働OSそれぞれの整合性取得方式、復元手順・確認方法と有効期限は未確定とする。

マスター用の対象一覧・信頼情報・操作対応のバックアップ範囲と復元、元のマスターを失った場合の復旧手順も未確定とする。上記のバックアップ状態の形式例だけではこれらの操作契約を充足しない。着手可否は[仕様充足の判定](../POLICIES.md#実装着手と仕様充足の判定)に従う。
