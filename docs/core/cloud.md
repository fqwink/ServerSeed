# SSHによるCloud環境の導入と保守

[文書一覧](../DOCUMENT_INDEX.md)

## ServerSeed Cloud

### 役割

ServerSeed Cloudは、マスターからSSHで到達したVPS・クラウドの実行環境を使い、対象OSの導入、構成適用および保守を行う。選択・接続・結果照合の制御は[マスター管理](../master/specification.md#自動処理の流れ)、共通の適用処理は[ライフサイクル](lifecycle.md)が担当する。

本書はSSH先の実行環境と対象ストレージに対する処理を定義する。

### 前提

接続前提と管理経路の保護は[Cloudの管理経路](../POLICIES.md#cloudの管理経路)、自動化の判断基準は[Cloud導入](../PRINCIPLES.md#cloud導入)を参照する。

VPSへのISO取得・接続やコンパイラー・Cargoの導入は要求しない。cloud-initの有無によって対象を除外せず、既存設定の扱いは[cloud-init](../POLICIES.md#cloud-init)に従う。

構成選択と非対応時の停止は[構成選択と継続管理](../POLICIES.md#構成選択と継続管理)に従う。接続先には[共通の対応範囲](product-scope.md#対応範囲)だけでなく、[構成ごとの担当仕様](product-scope.md#製品構成)の対応条件も照合する。マスター管理構成を選択した場合も[マスターの対応範囲](../master/specification.md#対応範囲)を適用し、Cloudからの選択を対応範囲の拡張や[構築条件](../POLICIES.md#実行入口と通常運用)の代替と扱わない。

### 実行環境と対象OS

「実行環境」はSSHサーバと導入・保守処理が動く環境、「対象OS」は管理対象ストレージ上の導入済みまたは導入予定OSとする。レスキュー・一時環境から接続する場合、両者は異なる。対象OSのないディスクでも、SSHの実行環境が用意されていれば検査対象に含める。

接続後、次を操作別に検査し、取得した情報を実行環境と対象へ分けて計画に対応付ける。

| 検査 | 対象 |
|---|---|
| 実行能力 | 実行環境のOS・CPU、利用可能コマンド、必要な権限、署名検証・転送・導入ツールと実行時依存 |
| ストレージ | 実行環境のルート・マウント・使用中ディスク、導入先の機器識別・容量・内容、バックアップ先との区別 |
| 起動・再接続 | 対象のブート方式、ブートローダーの設置能力、導入後のネットワーク・SSH到達経路、管理先の識別と復旧経路 |
| 対象OS | [共通状態判定](common-platform.md#共通状態判定)、導入済みOSへの[対応判定](product-scope.md#ubuntu-2404-lts判定)、構成適用時のsystemdと[必要機能](product-scope.md#ubuntuパッケージ管理前提) |

SSH実行環境の`/etc/os-release`を対象OSの情報として代用せず、空ディスクを接続先ルートと同一視しない。実行環境がUbuntu以外の場合の使用可否は下記の未確定契約へ対応付け、任意のOS・SSH実装を利用可能と判定しない。

### OSのインストール

OSのない対象に対しては、次の順序で処理する。対象の判定は[状態判定の優先順位](common-platform.md#状態判定の優先順位)に従う。

1. 実行環境と対象を検査し、OS導入と再接続までの実行能力を確認する。
2. マスターへ対象ディスクと導入予定の[対応OS](product-scope.md#対応範囲)、データへの影響、保全・起動・再接続の計画を返す。
3. マスターで確定した必須選択・破壊的操作の確認と計画を受け、適用直前に対象を再照合する。
4. 検証済みのOS資材を用いて対象へOSを導入し、ブートローダー、管理ユーザー、公開鍵と接続用ネットワークを構成する。
5. 対象ストレージから起動し、マスターから再接続して同じ対象と導入結果を確認する。
6. 本体の導入と初期セットアップへ進む。

OS導入機構、必要資材、接続先変更と識別検証の詳細は[未確定契約](#未確定契約)とする。能力が不足・不明な接続先へ、単にSSHへ接続できたことを根拠に処理を適用しない。

### 本体の導入

対象OSが対応OSとして起動している場合は、OS導入を挟まず本段階へ進める。マスターが固定した署名付き本体と検証情報を転送または対象から取得し、[初回の取得と配置](lifecycle.md#初回の取得と配置)を対象OS内で自動実行する。取得処理と[実行時依存](ci-cd.md#配布バイナリのターゲットとリンク)を検証する。

一時実行環境へ搬入した本体と、対象OSへ配置した本体の導入情報を取り違えない。呼び出しと操作記録は[実行側と対象側](lifecycle.md#実行側と対象側)に従う。

### 初期セットアップ

`ADOPTABLE`状態の対応OSに対して、次を行う。

1. マスターで選択した構成・入力・計画の照合と、対象OS、systemd、ネットワークおよび空き容量の検査
2. 現在のSSH接続および管理ユーザーの保護
3. 基本セキュリティ設定
4. 選択済み構成に必要なパッケージおよび実行基盤の導入
5. バックアップ、ログおよび監視設定
6. ServerSeed管理情報の作成
7. 最終検証

既存管理経路とルートディスクの保護は[Cloudの管理経路](../POLICIES.md#cloudの管理経路)に従う。

### 更新とバックアップ

マスターが確定した処理内で、構成・OS更新は[更新処理](lifecycle.md#更新処理)、本体変更は[self](cli.md#self)、バックアップは[実行と保存先](backups.md#実行と保存先)を使用する。対象VPSでの追加の手動開始を要求しない。更新後の再起動・再接続も計画に含める。

### 起動不能時の復旧

対象OSを起動できなくてもSSHの一時実行環境が利用できれば、マスターから対象を再検査して復旧計画を作成する。SSH自体が利用不能なら接続経路の準備を利用者へ案内し、再接続できるまで対象の変更処理へ進まない。事業者側のレスキュー起動・仮想メディア接続は、[責任範囲外の資源操作](product-scope.md#プロバイダー非依存)を自動化する根拠にしない。

設定復元・起動修復の範囲は[recover](cli.md#recover)、OS再導入は独立したOS導入計画として区別する。バックアップからの復元は[復元確認](backups.md#復元確認)とその未確定契約へ対応付ける。

### 未確定契約

| 対象 | 未確定の内容 |
|---|---|
| SSH実行環境 | 対応OS・CPU・実行コマンド、必要権限、起動環境の準備と利用条件。マスター側の接続・認証・制御契約は[担当仕様](../master/specification.md#未確定契約)へ集約 |
| OS導入方式 | 採用インストーラー・資材・固定版、ストレージの識別・除外・マウントと書き込み、ブート構成、入力・出力・失敗位置、適合する例外ID |
| 再起動と再接続 | 導入後の接続設定の生成・検証、対象の同一性とホスト鍵変更の確認、待機・時間制限・再試行、到達不能時の保全・復旧 |

これらの未確定部分に既存の`setup`や[Ubuntu対応判定](product-scope.md#ubuntu-2404-lts判定)だけを流用して、導入可能・実装着手可能とは判定しない。
