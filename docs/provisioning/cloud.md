# Cloud環境への導入

[文書一覧](../DOCUMENT_INDEX.md)

## ServerSeed Cloud

### 役割

ServerSeed Cloudは、VPSまたはクラウド事業者が準備した対応OSへServerSeedを導入し、共通定義に基づいて構成、更新および検証する。

導入後の操作入口は`serverseed`とする。

### 前提

ServerSeed Cloudは原則としてOSインストールを担当しない。利用者または事業者がUbuntu 24.04 LTSを作成し、SSH接続できる状態にする。

本体の導入経路は次をサポートし、VPSへISOを取得・接続することを必須にしない。

- cloud-init
- SSHからのセットアップ
- ローカルへ搬入した署名付きバイナリと検証情報

cloud-initはServerSeedの導入と対話セットアップの準備までを担当する。初回の構成選択は[初期構成選択と継続管理](../common-platform.md#初期構成選択と継続管理)に従い、利用者がSSHまたはコンソールから行う。選択完了後に構成適用を開始する。

### 本体の導入

利用者が事業者のUbuntuイメージを選び、SSHまたはコンソールの管理経路を確認した後、[初回の取得と配置](../development/implementation.md#初回の取得と配置)に従って本体を導入する。コンパイラーやCargoを対象VPSへ導入することは要求しないが、[実行時依存](../development/implementation.md#配布バイナリのターゲットとリンク)は確認する。

cloud-initでは、固定バージョンと事前確認済みキーリングを使った取得・検証・本体導入までを非対話で準備できる。利用者が指定した取得処理を自動化する場合も同じ検証を行い、失敗時は後続の準備を止める。取得したシェルを直接実行せず、検証済み本体の`self install`を使用する。既存のcloud-init設定を置き換えて導入手順を挿入しない。

準備完了後にSSHまたはコンソールで`serverseed setup`を実行する。対話できない環境を理由に既定構成を設定しない。

### 初期セットアップ

`ADOPTABLE`状態の対応OSに対して、次を行う。

1. 利用者による構成の手動選択と、OS、systemd、ネットワークおよび空き容量の検査
2. 現在のSSH接続および管理ユーザーの保護
3. 基本セキュリティ設定
4. 選択済み構成に必要なパッケージおよび実行基盤の導入
5. バックアップ、ログおよび監視設定
6. ServerSeed管理情報の作成
7. 最終検証

既存のSSH鍵、ネットワーク設定、cloud-initおよびゲストエージェントを、確認なしに削除または上書きしてはならない。汎用Cloud版ではルートディスクを再パーティションしない。

### 更新と起動不能時の復旧

通常の構成・OS更新は[更新処理](../operations/updates.md#更新処理)、本体だけの更新は[self](../interfaces/cli.md#self)を使用する。ISOからの再起動やOS再インストールを本体更新の条件にしない。

OSを起動できない場合は、利用者が事業者のレスキュー環境または対応Ubuntuの再作成を用意し、管理経路を回復してから、検証済み本体の導入と[バックアップからの復元確認](../operations/backups.md#復元確認)を行う。OS再作成に伴うデータ消去は通常の復旧操作に含めず、別途保全と利用者の判断を必要とする。事業者APIによる自動再構築は行わない。

独自ISOを接続できる環境では[USB用ISO](usb.md)を仮想メディアとして使用できるが、既存ルートディスクの再導入を自動選択しない。対応OS・systemd・管理権限・必要な機能を満たさないVPSでは、未対応理由を表示して変更を開始しない。
